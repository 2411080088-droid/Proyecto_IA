# ADR-001: Framework de aplicación

## 1. Título

ADR-001: Framework de aplicación.

## 2. Estado

Propuesto.

## 3. Contexto

Python 3.11+ y FastAPI están fijados. RF02 exige generar predicciones; RF01, consultar históricos; RF04, comparar pronóstico/real; RF05, calcular MAE/MAPE. RF01/03/04/05 fijan máximo cinco segundos bajo sus condiciones de prueba.

RNF02 exige clave de Gemini en variable de entorno, ausente del código y repositorio. RF06 exige MCP de solo lectura. Se utilizarán SQLite con datos simulados y frontend HTML/JavaScript simple. El equipo dispone de cuatro integrantes y diez semanas, sin integración con sistemas reales ni datos personales reales.

## 4. Alternativas consideradas

Las valoraciones de esfuerzo son estimaciones [INFERIDO].

| Alternativa | Ventajas y desventajas en este contexto |
|---|---|
| **A. FastAPI, versión estable vigente** | Cumple la restricción vigente. Su validación facilita definir endpoints de predicción, históricos, comparación y métricas, según la [documentación oficial](https://fastapi.tiangolo.com/features/). Gemini puede invocarse desde backend leyendo el entorno; debe comprobarse ausencia de exposición. Organización común favorece mantenimiento entre cuatro integrantes. Evita sustituir el framework durante diez semanas. No garantiza cálculos correctos ni rendimiento. |
| **B. Flask, versión estable vigente** | Su núcleo sencillo y extensible ofrece libertad organizativa, según la [documentación oficial](https://flask.palletsprojects.com/en/stable/design/). Permite los cuatro endpoints, pero exige acordar validaciones y convenciones. Gemini también puede usar la variable de entorno. Cuatro integrantes deberán mantener esas convenciones. Cambiar la restricción y adaptar código puede consumir plazo. |
| **C. Python 3.11+ con servidor HTTP y estructura propia mínima, sin framework web completo** | Control directo y estructura limitada. Los cuatro endpoints, tratamiento de solicitudes y validaciones requieren implementación propia. Gemini puede leer la variable de entorno; protegerla sigue siendo responsabilidad del código. Más responsabilidades propias dificultan mantenimiento entre cuatro integrantes y elevan riesgo para diez semanas. |

[VERIFICAR] Instalación, dependencias y compatibilidad efectiva de cada alternativa con el entorno concreto; no están confirmadas.

## 5. Decisión

Adoptar **FastAPI, versión estable vigente**: cumple la restricción y permite implementar las operaciones requeridas conservando SQLite y el frontend previsto.

## 6. Consecuencias

Positivas: continuidad tecnológica; [INFERIDO] menor adaptación.

Negativas: siguen siendo obligatorias pruebas funcionales, de seguridad, integridad y rendimiento.

## 7. Deuda aceptada

[INFERIDO] Limitar validación de capacidad a las cargas especificadas y diferir el agente. No diferir requisitos obligatorios.

## 8. Criterio de reversión antes de la semana 7

[INFERIDO] Cambiar si existe incompatibilidad irresoluble con Python 3.11+, imposibilidad demostrada de cumplir RNF02/RF06, o incumplimiento reproducible de cinco segundos atribuible al framework tras corregir código y consultas. Exigir que otra alternativa supere esas mismas pruebas y aprobar la modificación de la restricción.
